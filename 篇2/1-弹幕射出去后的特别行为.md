# 弹幕行为

本篇假定你已经完全明白了第一章的内容，作为第二章的开篇，我们会介绍弹幕在发射出去后要怎么继续操控。

当然，第一章第三篇给出了管理方式之一： 把弹幕ID存储起来，然后在Char_Pshoot()中控制，但这种方式麻烦而容易出错，比如弹幕被消弹\飞出场外后，弹幕ID就指向不存在的弹幕甚至新创建的弹幕了，这不方便也不安全，通常只在创建弹幕时这样做，具体的使用则会在第三章有提到（对，游戏源码中会使用到）。

在第一章第三篇中有一个属性dm(Bindex).feature，可以用于创建复杂的弹幕行为，这会在下一篇讲解。

有一种从老版本延续下来的写法则比较简明。

以上三种差不多就是所有方法了，不过在讲解前得讲点别的。

## 我们首先介绍`重载`与`继承`这两个概念

### 继承

在第一章中，我提到过继承像给这个类贴上标签，又说类是用来描述的东西。继承就是基于已有的描述继续添加新内容。

那为啥需要继承呢？这是因为程序不知道你的 MOD 如何描述这个类，所以提供了一个像模板似的描述。然后程序只要按照对模板的描述去找，就能找到你的 MOD 对内容的描述。比如，你可能会新建一个 `sub watashi()` 函数，程序不会主动调用这个函数，因为它原本的设计中不会考虑你会描述这样一个函数。但如果你重载一个函数，程序就可能知道怎么调用了。

### 重载

重载呢，就好比是对已有描述的内容进行重新描述。它允许修改标签中的描述，使描述外观是一样的，内容却发生了改变。通过重载，可以让我们写会被程序在特定情况下调用的函数与数值。

## 接下来我们介绍三种方法的实现

### 一、重载Char_Bmove()与Char_Bdeath()

在Def_Char标签中有描述这两个函数，我们可以重载他们。

```vbnet
    Public Overrides Sub Char_Bmove(Bindex As Integer)

    End Sub
    Public Overrides Sub Char_Bdeath(Bindex As Integer, more As Double)

    End Sub
```

他们的效果分别是在每一帧弹幕移动后调用Char_Bmove，参数是每个己方弹幕的ID，在特殊情况的一帧下会调用Char_Bdeath，参数是己方弹幕ID与描述调用原因的more，常见情况下是more = 0为击中敌机,1为出界,2为被消弹，其他情况下的不同more则通常只由你自己调用时才用（详细解释很奇怪，具体看下面怎么用吧）。

```vbnet
Public Overrides Sub Char_Bmove(Bindex As Integer)
    dm(Bindex).speed += 0.2'使弹幕的速度每帧加0.2
    If dm(Bindex).age > 60 Then'每个弹幕只存在1s，通常每秒六十帧
        dm(Bindex).Bdeath(3)'特殊情况下的消弹，这里的3会在调用Char_Bdeath时作为参数more输入
        '这里可能会有一个疑惑，为什么不是Char_Bdeath(Bindex, 3)，这是因为弹幕在消弹前需要有一些特殊的过程，在这个过程后才会使用Char_Bdeath，甚至不会调用Char_Bdeath
    End If
End Sub
Public Overrides Sub Char_Bdeath(Bindex As Integer, more As Double)
    If more = 3 Then'只有在你定义的特殊情况more = 3时
        dm(Bindex).B_real_delete()'注销弹幕，被消弹不一定弹幕会注销，注销后通常不允许再使用这个弹幕
        Exit sub'退出函数，防止后面再次注销弹幕
    End If
End Sub
```

我们这么一写，看起来就可以让每个弹幕每帧速度+0.2，1s后就消失。

于是你编译运行了一下，发现什么都没发生。

这是因为Bini(...)中有一个参数character，假如它输入的是0，就不会使用你自定义的Char_Bmove和Char_Bdeath。

你改了参数后，这些预期的效果就生效了，不过有个问题，东方的弹幕特殊行为通常多种多样，这里就一种行为有些说不过去。

再看向Bini(...)，有一个参数叫type，可以标记弹幕的种类，就像type = 0时弹幕是不存在的（未生成或已注销），给他赋值个1试试

```vbnet
Public Overrides Sub Char_Pshoot()
...
    Bini(...,type:=1)
...
End Sub
Public Overrides Sub Char_Bmove(Bindex As Integer)
    If dm(Bindex).type = 1 Then'只对type = 1的弹幕有效
        dm(Bindex).speed += 0.2
        If dm(Bindex).age > 60 Then
            dm(Bindex).Bdeath(3)
        End If
    End If
End Sub
Public Overrides Sub Char_Bdeath(Bindex As Integer, more As Double)
    If dm(Bindex).type = 1 Then'只对type = 1的弹幕有效
        If more = 3 Then 
            dm(Bindex).B_real_delete()
            Exit sub
        End If
    Else
        dm(Bindex).B_real_delete()'别忘了除了type = 1的弹幕也需要消弹哦，不然场上的弹幕会越来越多的
    End If
End Sub
```

现在你可以用经典的If Else If Else If...结构使不同弹幕有不同效果了（但是非常的丑），可以再简化一下，然后使用Bt枚举来标记type的值的可能类型，我们就得到了使用这种方法的通常模板（~~从1 + 1到微积分~~）

```vbnet
Public Overrides Sub Char_Bmove(Bindex As Integer)
    With dm(Bindex)'简写前缀
        Select Case .type'使用弹幕的type进行跳转
            Case Bt.A
                '弹幕行为A
            Case Else
                '未标记弹幕的行为
        End Select
    End With
End Sub
Public Overrides Sub Char_Bdeath(Bindex As Integer, more As Double)
    With dm(Bindex)
        Select Case .type
            Case Bt.A
                '弹幕行为A
            Case Else
                '未标记弹幕的行为
        End Select
    End With
End Sub
```

理论上来说，除了可能看起来嵌套的层数多的离谱，这个方式已经可以满足几乎所有弹幕移动方式的需求了，包括但不限于追踪，旋转，变大变小，渐显渐隐。
